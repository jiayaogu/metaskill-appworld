## APIs TO USE FOR SPECIFIC INFORMATION
[api-00004] You can use the "supervisor" app to get information about my accounts and use the "phone" app to get information about friends and family.

[api-00013] Amazon purchase API schemas: search_products returns a list of product dicts with product_id, seller_id, product_type, name, price, inventory_quantity, rating, variations; show_seller returns a dict with seller_id, name, rating; show_payment_cards returns a list of dicts with payment_card_id, card_name; show_addresses returns a list of dicts with address_id, name; add_product_to_cart returns a message dict; show_cart returns a cart dict with cart_items; place_order returns a dict with order_id and message; show_order returns an order dict with address_id, payment_card_id, and order_items.
[api-00017] For highest-rated seller tasks, do not treat seller_ids seen in search_products as the complete seller universe. Also enumerate candidate sellers for the category using search_sellers and/or show_product_feature_choices(product_type=...), cross-check with product seller_ids, fetch authoritative ratings with show_seller, and break seller-rating ties deterministically (e.g., lowest seller_id).
[api-00020] Amazon category-purchase schema clarifications: supervisor.show_account_passwords returns a list of {'account_name', 'password'}; amazon.login returns {'access_token', 'token_type'}; search_products and show_product include name and description, which should be used for semantic validation; show_product_feature_choices(product_type=...) returns {'colors': [...], 'relative_sizes': [...], 'sellers': [{'seller_id': int, 'name': str}]} and does NOT include seller rating, so call show_seller for each candidate seller_id to get authoritative rating; show_cart returns cart_items with quantity; show_order returns order_items with ordered_quantity.
[api-00024] Amazon payment-card schema clarification: show_payment_cards returns payment_card_id, card_name, owner_name, card_number, expiry_year, expiry_month, and cvv_number. When no payment card is specified, do not select by arbitrary ID; validate expiry_year/expiry_month before place_order.
[api-00031] Amazon search_products rating filters: for minimum product/seller rating tasks, pass min_product_rating and min_seller_rating (with product_type/query) to reduce noise, but treat these filters as prefilter only; still verify seller ratings with show_seller and product details with show_product.
[api-00034] Amazon wishlist schema: show_wish_list returns a list of dicts with product_id, product_name, quantity, price; it does NOT include product_type, inventory_quantity, length/width/height, or variations. For wishlist items with physical constraints, derive candidate product_ids from product_name, then call show_product(product_id=...) for each candidate to get authoritative dimensions, inventory, product_type, name/description, and variations.
[api-00044] Amazon show_product full schema: returns product_id, seller_id, product_type, name, description, price, delivery_days, inventory_quantity, weight, length, width, height, color, relative_size, rating, num_product_reviews, num_product_questions, and variations (list of dicts with product_id, relative_size, color). For physical-fit wishlist purchases, use length/width for fit (allow swapped orientation only if task does not fix orientation), product_type/name/description for semantic validation, and inventory_quantity for stock.
[api-00047] Amazon product evidence API schemas: show_product_reviews(product_id=..., is_verified=True, page_index=..., page_limit=...) returns a list of review dicts with review_id, product_id, is_verified, rating, title, text, created_at, and user{name,email}. show_product_questions(product_id=..., page_index=..., page_limit=...) returns a list of question dicts with question_id, question, created_at, and user{name,email}; it does NOT include an is_verified flag. show_product_question_answers(question_id=..., is_verified=True, page_index=..., page_limit=...) returns a list of answer dicts with question_answer_id, question_id, is_verified, answer, created_at, and user{name,email}. Verified-purchaser status must be checked on reviews and answers, not on questions.
[api-00056] Amazon evidence product/API schema clarification: search_products may return accessories or variant listings; show_product.variations should not be used for evidence unless requested. Normalize product names (lowercase, hyphens to spaces) to match variants such as 'e-reader', 'eReader', and 'e reader'. Evidence endpoints return lists directly; inspect docs for access_token requirements and check for error dicts.
[api-00058] Amazon search_products evidence schema: the documented parameters include query, product_type, color, relative_size, price/rating filters, seller_id, page_index, page_limit, and sort_by, but NOT access_token. For product evidence tasks, call search_products without access_token unless the current API doc explicitly lists it; narrow device/laptop searches by adding product_type (e.g., 'laptop') along with the exact query to reduce irrelevant accessories and unrelated categories, then still derive the product_id programmatically from exact normalized name matches.
[api-00062] Amazon cart-state schema and restoration APIs: show_cart returns a dict with promo_code, promo_valid, and cart_items; each cart_item includes product_id, product_name, delivery_days, quantity, price, gift_wrap_quantity. show_order order_items include ordered_quantity and gift_wrap_quantity. Relevant mutation APIs include clear_cart, add_product_to_cart, add_gift_wrapping_to_product, remove_gift_wrapping_from_product, apply_promo_code_to_cart, and remove_promo_code_from_cart. To revert a cart exactly, snapshot per-item gift_wrap_quantity and cart-level promo_code/promo_valid, inspect the mutation API docs, re-add items, reapply gift wrapping/promo code when present, and verify full cart equality rather than only product_id->quantity.

def half_up_whole_no_decimal(price, quantity):
    s = str(price).strip()
    if 'e' in s.lower():
        total = float(s) * int(quantity)
        return int(total + 0.5 + 1e-9)

    if sign < 0:
        s = s[1:]
    if '.' in s:
        whole, frac = s.split('.', 1)
    else:
        whole, frac = s, ''
    whole = whole or '0'
    frac = frac.rstrip('0')
    digits = whole + frac
    scale = 10 ** len(frac)
    value = int(digits or '0') * int(quantity)
    return sign * int((2 * value + scale) // (2 * scale))
